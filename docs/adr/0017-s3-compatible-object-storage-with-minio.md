# Object storage uses an S3-compatible boundary with MinIO by default

> **2026-08 superseded**：检索路径不再依赖对象存储——Qdrant 单容器部署已移除 MinIO 与 etcd（[ADR 0075](0075-qdrant-replaces-milvus-as-the-hybrid-retrieval-engine.md)、[version-baseline](version-baseline.md) §2）。`ObjectStorage` 端口与 S3 兼容边界仍为未来文档/产物存储保留；v1 Compose 不再提供对象存储，dev/test 用本地文件系统适配器。

MedicalRAG stores original documents, MinerU request material, extraction artifacts, and derived assets behind an S3-compatible object-storage interface. Docker Compose provides MinIO for local development and automated test environments; production may use a managed S3-compatible service without changing domain or ingestion code. Object keys are generated by the application, are not derived directly from user filenames, and are separated by Workspace, Document, Ingestion Run, artifact type, and retention class.

> **2026-08 更新（AGPL 最后版钉版）**：MinIO 社区版已停止维护（README 明示「NO LONGER MAINTAINED」，Docker Hub `minio/minio` 已 ARCHIVED，最后 OSS RELEASE `2025-10-15T17-29-55Z` / 最后 Docker Hub 镜像 `RELEASE.2025-09-07T16-13-09Z`）。Compose 钉这两个 AGPLv3 tag 之一（安全/CVE 版优先，若有 ghcr/quay 镜像）。风险：无后续安全补丁，需接受；维护替代为 **AIStor Free**（单节点许可）或 **本地文件系统**（dev/test 与 <1TB 单后端：经 `ObjectStorage` 端口 + `fsspec`/`s3fs`/`aiofiles` 实现，浏览器直读改登录鉴权应用路由）。本 ADR 的 S3 兼容边界与键规划不变。

## Consequences

- FastAPI and workers never use local process disks as the source of truth for ingestion artifacts.
- MinerU submissions can use short-lived, least-privilege object references or provider-supported upload flows.
- Bucket policies, encryption, lifecycle expiration, malware scanning, checksum verification, and access logging are deployment responsibilities.
- Tests must be able to run against an isolated MinIO instance or an S3-compatible test double.
