## Destination

Produce a complete, implementation-ready specification for a behavior-equivalent migration of Ragent into MedicalRAG using the approved Python 3.14/uv, FastAPI, PostgreSQL, Redis, TaskIQ, Qdrant, Aegra, Vite SPA (Nginx/Vite same-origin proxy), React, assistant-ui, and Docker Compose stack. The route is clear when no unresolved decision can block development; this map does not implement the system.

## Notes

- Domain: evidence-first medical RAG workbench with Ragent as the behavior reference.
- Skills to consult: `grill-with-docs`, `domain-modeling`, `research`, `codebase-design`, and the official documentation for every selected runtime or provider.
- Standing preferences: external APIs for generation, dense embeddings, reranking, and MinerU; Aegra's official OTEL export with Phoenix as the only AI/RAG Trace backend; structured logs, metrics, and health checks for API/Worker diagnostics; PostgreSQL business run/audit records only; root `docker-compose.yml`; modular monorepo; official adapters wherever available; direct streaming without a post-generation blocking gate.
- Research gate: no implementation-final document may be written or treated as locked until the official documentation and coding-standard research tickets are closed and their findings are reconciled with the domain decisions.
- The local specification and ADRs are supporting artifacts; this map tracks the remaining decisions that must be resolved before implementation.

## Decisions so far

- [Ragent behavior parity scope and supported source policy](tickets/ragent-behavior-parity-scope-and-supported-source-policy.md) — full capability parity is the target, with only the approved document extensions in scope.
- [Ragent capability migration matrix is implementation-complete](tickets/ragent-capability-migration-matrix.md) — the complete matrix is recorded across the [stack replacement matrix](../reference/stack-replacement-matrix.md) (tech stack) and the [behavior parity matrix](../reference/behavior-parity-matrix.md) (events, failure, admin routes); every audited capability carries a status, target, and reference; parity fixtures remain with the testing decision.
- [Runtime ownership and streaming boundary](tickets/runtime-ownership-and-streaming-boundary.md) — Aegra owns Agent Thread/Run execution and streaming; FastAPI owns business APIs and domain services.
- [Aegra, FastAPI, and worker runtime contract](tickets/aegra-fastapi-arq-worker-runtime-contract.md) — four processes (api / agent / worker / web+nginx) with own composition roots; Thread/Run handoff via PostgreSQL Conversation↔Aegra thread mapping; TaskIQ job + transactional outbox (SKIP LOCKED + pg_notify relay, stable job ids), worker-side retry with PostgreSQL-backed failure/replay, and per-process readiness (ADR 0073).
- [Native Agent Protocol v2 browser runtime](tickets/frontend-contracts-and-assistant-ui.md) — assistant-ui uses the official `@assistant-ui/react-langchain/useStreamRuntime` over Aegra v2 SSE/commands; no custom runtime or protocol bridge.
- [Vite SPA with a same-origin Nginx/Vite proxy](../adr/0070-vite-spa-with-nginx-proxy-is-the-frontend-runtime.md) — TanStack Start Node SSR is removed; the frontend is a Vite SPA with Nginx (prod) / Vite `server.proxy` (dev) proxying `/api` + `/api/agent`.
- [Qdrant replaces Milvus/MinIO as the unified Hybrid Retrieval engine](../adr/0075-qdrant-replaces-milvus-as-the-hybrid-retrieval-engine.md) — supersedes ADR 0011/0017/0026/0027/0052/0054/0056; Qdrant is a single-container dense + sparse/BM25 Hybrid Retrieval engine (fastembed static sparse model, RRF k=60) with no MinIO/etcd dependency; the `ObjectStorage` port is retained behind a local filesystem adapter in v1.
- [Official Aegra, Agent Protocol v2, assistant-ui, and frontend-stack research](tickets/official-agent-and-frontend-stack-research.md) — official docs confirm the v2-native adapter, same-origin auth boundary, Node 24/TypeScript 6 frontend baseline, and split pnpm/Turborepo/uv responsibilities.
- [Qdrant Hybrid Retrieval boundary](../adr/0075-qdrant-replaces-milvus-as-the-hybrid-retrieval-engine.md) — Qdrant is the sole retrieval engine with dense plus sparse/BM25 Hybrid Retrieval and external reranking.
- [Qdrant Hybrid Retrieval schema and ranking contract](../adr/0075-qdrant-replaces-milvus-as-the-hybrid-retrieval-engine.md) — one collection per Embedding Schema Version with a fastembed `Qdrant/bm25` static sparse field; RRF (k=60) via Qdrant's built-in RrfQuery; scalar authorization + `is_eligible` payload filters; the external reranker re-scores after fusion.
- [TaskIQ durable workflow boundary](tickets/arq-durable-workflow-boundary.md) — TaskIQ executes durable asynchronous application workflows; it does not replace Aegra's agent runtime (ADR 0073).
- [TaskIQ replaces RocketMQ as the durable job queue](../adr/0073-taskiq-replaces-arq-as-the-durable-job-queue.md) — supersedes ADR 0063 on the library axis: the Worker runs ingestion, extraction, embedding, indexing, reconciliation, and operational jobs with worker-side retries, stable job ids, and PostgreSQL-backed failure/replay; transactional publication uses a PostgreSQL outbox.
- [uv manages a Python 3.14 runtime baseline](../adr/0064-uv-manages-python-314-runtime.md) — every Python member declares `requires-python >=3.14` (lower bound only); a `.python-version` file pins the 3.14.x minor baseline shared by Docker, CI, and development.
- [Aliyun mirrors for pnpm, uv, and apt](../adr/0065-aliyun-mirrors-for-pnpm-uv-and-apt.md) — development, CI, and image builds use Aliyun mirrors; lockfiles remain canonical.
- [UUIDv7 is the universal business identifier](../adr/0066-uuidv7-is-the-universal-business-identifier.md) — every business record uses UUIDv7 via Python 3.14 `uuid.uuid7()`; TaskIQ job ids derive from aggregate ids.
- [Operator console charting](../adr/0067-operator-console-charting-recharts-and-g6.md) — recharts for dashboard KPIs and @antv/g6 for the intent-tree editor.
- [Document preview](../adr/0068-document-preview-mainstream-per-format-renderers.md) — native md/txt/images plus pdfjs-dist (PDF), docx-preview (docx), and SheetJS + TanStack Table (xlsx); pptx is a typed unsupported in v1, served via the application's ObjectStorage port (local filesystem adapter in v1).
- [Deep-thinking is an Analysis Depth option](../adr/0069-deep-thinking-is-analysis-depth-option.md) — the toggle selects an analysis-capable Model Target, deeper retrieval budget, and an evidence-synthesis stage without changing the Safety Boundary.
- [MCP and alternate retrieval backends are out of scope](tickets/mcp-and-alternate-retrieval-backends-are-out-of-scope.md) — no MCP compatibility, pgvector, Elasticsearch, Neo4j, or LightRAG target service.
- [External provider, ingestion, identity, safety, and streaming baseline](tickets/external-provider-ingestion-identity-safety-and-streaming-baseline.md) — approved file formats use MinerU API, authentication is application-owned, the fixed disclaimer is required, and generated tokens stream directly.
- [Identity, Workspace, and Safety Boundary](tickets/identity-workspace-and-safety-boundary.md) — app-owned Argon2id identity with Redis sessions in secure cookies, Workspace isolation with member roles plus an operator role, ownership on every record, safety class with pre-retrieval short-circuit, and egress limited to de-identified content.
- [Ingestion and MinerU state machine](tickets/ingestion-and-mineru-state-machine.md) — nine TaskIQ job stages with forward-only durable transitions; MinerU callback-first with polling reconciliation and checksum validation; immutable raw artifacts; per-stage retry with `UNIQUE(ingestion_run_id, stage)` idempotency; documents are ineligible until validation, indexing, and the reviewed Publication complete.
- [External provider and data-egress contracts](tickets/external-provider-and-egress-contracts.md) — application-owned Generation/Embedding/Reranker/MinerU ports; platform-owned credentials; bounded timeout/retry/quota with a Redis circuit; direct streaming without a blocking gate; evidence-insufficiency fallback on total provider failure.
- [Compose profiles and operational topology](tickets/compose-topology-and-operations.md) — root `docker-compose.yml` with core services (PostgreSQL/Redis/Qdrant) off-profile, `dev`/`test`/`prod` profiles, Nginx `/api`+`/api/agent` proxy, named volumes + healthcheck ordering, manifest-coordinated backups, and Aliyun mirror configuration; no RocketMQ broker, no MinIO/etcd. **2026-08 update**: application services (api/agent/worker/web) are now default-on with `docker compose up -d` (profiles no longer gate them); Aegra uses a dedicated `medicalrag_aegra` database created by an idempotent `db-init` one-shot service; self-hosted Phoenix (Postgres-backed, `medicalrag_phoenix` DB) remains the optional `observability` profile (ADR 0082).
- [Testing, parity evidence, and release gates](tickets/testing-quality-and-release-gates.md) — unit/contract/integration/E2E pyramid plus `eval-retrieval` on every PR and `eval-answer` on release candidates; security, accessibility, migration, observability, and failure-injection coverage; a capability is parity-complete only when its migration-matrix row has a passing fixture.
- [Official monorepo and toolchain research](tickets/official-monorepo-and-toolchain-research.md) — first-party uv, pnpm, Turborepo, Python packaging, TanStack Start, TypeScript, lint, formatting, and test guidance has been captured for review.
- [Official Langfuse observability research](tickets/official-langfuse-observability-research.md) — Python SDK v4, Aegra integration ownership, LangChain callback scope, HTTP OTLP, masking, sampling, fail-open, and Compose/SaaS boundaries are captured for review.
- [Official production tracing research](tickets/official-trace-architecture-and-backends-research.md) — the comparison remains a historical research record; the target does not deploy a separate system tracing backend.
- [Official Python backend and data-stack research](tickets/official-python-backend-and-data-stack-research.md) — research captured and reconciled to Python 3.14 + TaskIQ/outbox; cp314 wheels and the aegra-api 3.14 baseline remain implementation gates.
- [Official Milvus, MinerU, and object-storage research](tickets/official-retrieval-ingestion-and-storage-research.md) — research captured and reconciled; superseded on the storage axis by ADR 0075 (Qdrant replaces Milvus/MinIO); MinerU schema details graduate to the open ingestion ticket.
- [Official DevOps, quality, security, and observability research](tickets/official-devops-quality-security-and-observability-research.md) — research captured and reconciled to TaskIQ, Python 3.14, Aliyun mirrors, Qdrant single-container topology, and the Vite SPA + Compose core-services-not-on-profiles topology.
- [Aegra-only Langfuse observability](../adr/0059-langfuse-is-a-fail-open-operational-observability-sink.md) — Aegra owns the only Langfuse integration, with scrubbed AI/RAG observations and fail-open export.
- [Langfuse-only AI/RAG Trace](../adr/0062-langfuse-is-the-only-ai-rag-trace-backend.md) — Langfuse is the only Trace backend; PostgreSQL stores business run/audit records and structured logs/metrics cover infrastructure diagnostics.
- [Langfuse is self-hosted as an optional observability profile](../adr/0072-langfuse-self-hosted-optional-observability-profile.md) — v1 self-hosts Langfuse in an optional `observability` Compose profile (MIT core, data in-network); Cloud is a later option; export stays fail-open.
- [Shared infra package and pruned package graph](../adr/0060-shared-infra-package-and-pruned-package-graph.md) — use `packages/infra`, keep composition roots in each app, and remove speculative UI/testkit/config/common/utils packages.
- [Monorepo toolchain and package boundaries](tickets/monorepo-toolchain-and-package-boundaries.md) — OpenAPI single-direction contract generation; Turborepo orchestrates only JS, uv owns Python, CI coordinates the two; `medical-core` is a narrowed domain seam with the chat pipeline in `apps/agent`; the researched directory layout is adopted.
- [OpenAPI single-source contract generation](../adr/0071-openapi-single-source-contract-generation.md) — FastAPI → OpenAPI → TypeScript types with a CI drift gate; `/api/agent` is Agent Protocol v2 and is exempt from generation.
- [Prefer popular third-party libraries](../adr/0074-prefer-popular-third-party-libraries.md) — OpenAI providers use the `openai` SDK, structured logging uses `loguru`, streaming uses the SDK + FastAPI built-ins; custom code is reserved for the framework-free domain seam (ADR 0025) and product-specific algorithms.
- [TaskIQ replaces arq](../adr/0073-taskiq-replaces-arq-as-the-durable-job-queue.md) — implementation-resolved: arq 0.28's `redis<6` upper bound conflicts with the pinned redis-py 8.1 baseline (version-baseline gate 3); the Worker uses TaskIQ + taskiq-redis, preserving ADR 0063's durable-workflow boundary.
- Ingestion stage count resolved to nine — implementation-resolved: the closed ingestion ticket lists eight stages (indexing → published), but spec/map say "nine" and the publication gate names validation before the reviewed Publication; `validating` is the ninth stage (accepted → … → indexing → validating → published). Recorded in `medicalrag_core/ingestion/state_machine.py`; ticket `ingestion-and-mineru-state-machine.md` is superseded by this resolution.
- [Chunking adds size caps, sentence-boundary splits, overlap, and atomic tables](../adr/0077-chunking-adds-size-caps-sentence-boundary-splits-overlap-and-atomic-tables.md) — amends ADR 0034: ~500-token cap with sentence-boundary splits, 10–15% overlap, tables stay atomic; chunk ids and provenance unchanged.
- [Chunks carry generated background context before embedding](../adr/0078-chunks-carry-generated-background-context-before-embedding.md) — flag-gated enrichment generates a 50–100 token situating note per Chunk; the same contextualized text feeds dense and sparse channels; enabling it bumps the Embedding Schema Version and requires full re-index.
- [Documents support unpublish and delete with cascading index cleanup](../adr/0079-documents-support-unpublish-and-delete-with-cascading-index-cleanup.md) — unpublish clears eligibility (soft, reversible); delete cascades Qdrant points by document_id via outbox + worker; periodic orphan-Chunk reconciliation.
- [Production hardening baseline](../adr/0080-production-hardening-baseline.md) — CI-enforced gates (ruff/pyright/pytest cov≥80/contract/turbo/security-audits/image-builds), auth-event-only workspace writes + login IP rate limit, request_id middleware, Prometheus `/metrics`, event `to_payload` single source, worker pydantic-settings + outbox poison-message cap, migrate-as-job + non-root multi-stage images + loopback-only middleware ports, compose `test` profile, web vitest/Playwright layers, xlsx dependency removed (preview degraded).
- [openai SDK 3.x and httpx2 alignment](../adr/0081-openai-sdk3-httpx2-alignment.md) — openai>=3.3 with all first-party provider code on `httpx2 as httpx` (no process-wide alias); aegra-cli pinned 0.10.4 behind Compose gate; qdrant client/server synced 1.19; TanStack Table v9 via shared `AppTableFeatures` in web `lib/table.ts`.
- [Phoenix replaces Langfuse as observability backend](../adr/0082-phoenix-replaces-langfuse-as-observability-backend.md) — the optional `observability` profile self-hosts Phoenix (single container, Postgres-backed `medicalrag_phoenix` DB, auth + system API key) instead of the Langfuse stack; `OTEL_TARGETS=PHOENIX` keeps Aegra as the sole fail-open OTLP owner; `chat_runs.langfuse_trace_id` renamed `trace_id` (Aegra thread_id → Phoenix `/redirects/sessions/{id}` deep link).
- [pnpm 12（Rust 重写）作为 JS 包管理器基线](../adr/0083-pnpm-12-js-package-manager-baseline.md) — `packageManager` 钉 12.1.0（next-12 分发，npm `latest` 仍指 11 线）；lockfile 9.0 与 `allowBuilds`/`minimumReleaseAgeExclude` 零迁移，未识别 workspace 设置升级为报错；CI 从 `pnpm/action-setup` 迁移到官方 `pnpm/setup@v2`（runtime: node@24）；web 镜像保留 corepack 取钉版（pnpm 12 静态链接，无需 libatomic）。
- [TypeScript 7 原生编译器作为前端类型检查基线](../adr/0084-typescript-7-native-compiler-baseline.md) — 取代 §4 的 TS 6.0.2 单钉与"TS7 勿主包直升"限制（typescript-eslint 属幽灵依赖，lint 实际用 oxlint）；官方双别名并排：`@typescript/native`（TS 7.0 原生 `tsc`，build/typecheck，实测 4.5s→1.4s）+ `typescript`→typescript6 保留（openapi-typescript 运行时消费 TS 6 JS API，TS 7.0 不带 API）；tsconfig 新增 `erasableSyntaxOnly`，TS7 新默认（noUncheckedSideEffectImports/stableTypeOrdering）自动生效；TS 7.1 交付 API 后收敛单包。

## Not yet specified

- Vite SPA route ownership (TanStack Router), the OpenAPI contract-generation output, assistant-ui state/data parts, accessibility behavior, and frontend test seams.

## Out of scope

- Implementing application code during the Wayfinder planning effort.
- Clinical diagnosis, autonomous triage, prescribing, dosage calculation, or regulated clinical workflow certification.
- MCP protocol compatibility and external MCP server integration.
- MCP parameter extraction and MCP tool routing.
- URL/Feishu ingestion, Ollama, local model servers, and unsupported standalone packages (`ui`, `testkit`, `config`, `common`, `utils`).
- Alternate retrieval databases and a local MinerU GPU pipeline.
