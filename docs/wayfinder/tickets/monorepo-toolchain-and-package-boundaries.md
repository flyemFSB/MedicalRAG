## Question

What is the final independent uv/pnpm workspace layout, dependency direction, contract-generation boundary, task orchestration policy, and exact responsibility of `packages/medical-core`?

## Accepted baseline

- Python workspace members are `apps/api`, `apps/agent`, `apps/worker`, isolated `apps/evaluation`, `packages/medical-core`, `packages/infra`, and the Python side of `packages/contracts`; JavaScript workspace members are `apps/web` and the TypeScript side of `packages/contracts`.
- `packages/infra` is the renamed shared adapter package. It contains concrete PostgreSQL, Redis, Milvus, arq, object-storage, external-provider, business run/audit, structured logging, metrics, and health adapters. Aegra owns the separate graph/LLM Langfuse integration; `packages/infra` does not contain an application-wide Trace provider. It is not placed inside `apps/api` because Agent and Worker share those adapters.
- Every application owns its composition root and settings. The repository root `infra/` directory contains Compose/Docker configuration and must not be imported as Python application code.
- `packages/ui`, `packages/testkit`, `packages/config`, `packages/common`, and `packages/utils` are removed from the target graph. Their responsibilities stay with the consuming application/member or a named domain/adapter module.
- Turborepo orchestrates only JS/TS tasks; uv owns Python dependency resolution and commands. Node.js 24 is the frontend runtime baseline.
- All Python workspace members declare `requires-python >=3.14` (lower bound only) and a root `.python-version` file pins the 3.14.x minor baseline shared by Docker, CI, and development machines ([ADR 0064](../../adr/0064-uv-manages-python-314-runtime.md)).
- pnpm uses the npmmirror registry (`https://registry.npmmirror.com`) and uv uses the Aliyun PyPI index (`https://mirrors.aliyun.com/pypi/simple/`) for development and CI; apt sources in Docker base images use the Aliyun mirror where builds need it. Lockfiles and integrity hashes remain canonical ([ADR 0065](../../adr/0065-aliyun-mirrors-for-pnpm-uv-and-apt.md)).

## Resolution

The final workspace layout, dependency direction, contract boundary, task orchestration, and `medical-core` responsibility are settled:

- **Contract-generation boundary** — OpenAPI single-direction generation. FastAPI is the authoritative source for `/api` contracts: Pydantic → OpenAPI → TypeScript types generated by `openapi-typescript` (or equivalent), with a CI drift gate. `/api/agent` is exempt — its contract is Agent Protocol v2, so `packages/contracts` only pins the protocol version and the event envelope ([ADR 0071](../../adr/0071-openapi-single-source-contract-generation.md)).
- **Python version** — `requires-python >=3.14` (lower bound only) with a root `.python-version` pinning 3.14.x ([ADR 0064](../../adr/0064-uv-manages-python-314-runtime.md)).
- **Task orchestration** — Turborepo orchestrates only JS/TS tasks; uv owns Python dependency resolution and commands; CI coordinates the two sides with top-level stages. Turborepo does not drive Python tasks.
- **`packages/medical-core` is a narrowed domain seam, not a merge target** — it is retained (not deleted, not merged into `apps/agent` or `packages/contracts`) and holds entities, value objects, state machines, policies, ports, and deterministic domain services shared by API/Agent/Worker. Chat-pipeline orchestration (LangGraph `StateGraph` assembly, node bindings, and the Aegra runtime hookup) lives in `apps/agent`; ingestion domain logic lives in `apps/worker`; `medical-core` carries no LangGraph/Aegra/SQLAlchemy/FastAPI dependencies ([ADR 0025](../../adr/0025-shared-medical-application-package-for-fastapi-and-aegra.md)).
- **Directory layout** — adopt the researched layout in `docs/research/monorepo-best-practices.md` §3, as updated for this plan: Vite SPA (`apps/web`, [ADR 0070](../../adr/0070-vite-spa-with-nginx-proxy-is-the-frontend-runtime.md)), an arq worker replacing RocketMQ consumers, OpenAPI-generated `packages/contracts/typescript/generated`, and a Nginx reverse proxy for `/api` + `/api/agent`.
