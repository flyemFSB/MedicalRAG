# F4: AI/LLM & RAG engineering standards

## Findings

### [1] LangGraph is a low-level orchestration runtime that deliberately mixes deterministic, hand-coded steps with LLM-driven agentic steps in one graph, rather than abstracting prompts or architecture.
- quote: "LangGraph gives you fine-grained control to mix deterministic, hand-coded steps with LLM-driven agentic steps in the same graph, so you can build bespoke agents that behave exactly the way your application requires."
- url: https://docs.langchain.com/oss/python/langgraph/overview
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [2] LangGraph production persistence requires a durable checkpointer (e.g. PostgresSaver); InMemorySaver is explicitly unsuitable because checkpoints vanish on process restart, and thread_id must stay under 255 characters for PostgresSaver.
- quote: "MemorySaver and InMemorySaver store checkpoints in RAM. When the process restarts, all checkpoints are lost. Fix: Use a persistent checkpointer for production: PostgresSaver: PostgreSQL with async support"
- url: https://docs.langchain.com/oss/python/langgraph/persistence
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [3] LangGraph distinguishes short-term thread-scoped memory (checkpointers) from long-term cross-thread memory (stores); production apps commonly use both, with checkpointer keyed by thread_id.
- quote: "Checkpointers persist a thread's graph state as checkpoints. Use them for short-term, thread-scoped memory... Stores persist application-defined data outside the graph state. Use them for long-term, cross-thread memory"
- url: https://docs.langchain.com/oss/python/langgraph/persistence
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [4] LangGraph HITL interrupts are implemented via a special exception and resume by re-running the entire node from its start; therefore side effects before interrupt() must be idempotent and interrupt() must not be wrapped in bare try/except.
- quote: "Because interrupts work by re-running the nodes they were called from, side effects called before interrupt() should (ideally) be idempotent."
- url: https://docs.langchain.com/oss/python/langgraph/interrupts
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [5] LangGraph graph design centers on State + Nodes + Edges compiled into a StateGraph, with reducers controlling how node updates merge into shared state; nodes may be pure code or LLM calls, and checkpointer re-execution requires idempotent node logic.
- quote: "In short: nodes do the work, edges tell what to do next. ... Design node logic so re-execution does not corrupt state. If a node inserts a database row, running it twice should not create duplicate rows unless that is intentional."
- url: https://docs.langchain.com/oss/python/langgraph/graph-api
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [6] RAGAS positions production LLM evaluation as moving from ad-hoc "vibe checks" to systematic evaluation loops with experiments, metrics, and datasets, not one-off manual review.
- quote: "Ragas is a library that helps you move from \"vibe checks\" to systematic evaluation loops for your AI applications."
- url: https://docs.ragas.io/en/stable/
- source_type: primary
- published: 2025-12-09 (page footer)
- confidence: high

### [7] RAGAS Faithfulness scores factual consistency of a response against retrieved context as the fraction of response claims supported by that context, on a 0–1 scale.
- quote: "Faithfulness Score = Number of claims in the response supported by the retrieved context / Total number of claims in the response"
- url: https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/
- source_type: primary
- published: 2025-12-09
- confidence: high

### [8] RAGAS Context Recall measures retrieval completeness by attributing reference-answer claims to retrieved context; non-LLM and ID-based variants exist when reference contexts or document IDs are available, avoiding LLM-as-judge cost for pure retrieval evals.
- quote: "Context Recall = Number of claims in the reference supported by the retrieved context / Total number of claims in the reference"
- url: https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/
- source_type: primary
- published: 2025-12-09
- confidence: high

### [9] The canonical RAG metric suite for production covers retrieval quality (Context Precision, Context Recall, Context Entities Recall, Noise Sensitivity) separately from generation quality (Faithfulness, Response Relevancy), plus agent metrics (Tool Call Accuracy/F1, Agent Goal Accuracy, Topic Adherence).
- quote: "Retrieval Augmented Generation: Context Precision, Context Recall, Context Entities Recall, Noise Sensitivity, Response Relevancy, Faithfulness... Agents or Tool use cases: Topic adherence, Tool call Accuracy, Tool Call F1, Agent Goal Accuracy"
- url: https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/
- source_type: primary
- published: 2025-12-09
- confidence: high

### [10] LangSmith treats traces as the production record of agent behavior used to debug failures, monitor quality, and build evaluation datasets, with dashboards, alerts, online evaluations, and user-feedback annotation as first-class ops surfaces.
- quote: "Traces are the record of what your agents did in production. Use them to debug failures, monitor quality, and build the datasets you evaluate against."
- url: https://docs.langchain.com/langsmith/observability
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [11] Production prompt/context management should version non-code agent assets (prompts, retrieval contexts, skills) separately from application code, promote them through environments, and let domain experts edit without deploys.
- quote: "Prompts, retrieval context, skills, and task instructions change more often than the application code around them... store, version, review, and update the non-code parts of your agent so you can change behavior without a full deploy"
- url: https://docs.langchain.com/langsmith/prompt-engineering
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [12] Pydantic AI standardizes structured outputs via three explicit modes—Tool Output (default, widest model support), Native Output (model JSON-schema structured outputs), and Prompted Output (least reliable)—with Pydantic validating model-returned data and ModelRetry driving correction loops.
- quote: "Pydantic AI implements three different methods to get a model to output structured data: 1. Tool Output... 2. Native Output... 3. Prompted Output... often the least reliable approach"
- url: https://ai.pydantic.dev/output/
- source_type: primary
- published: unknown (current as of 2026-09)
- confidence: high

### [13] OWASP LLM security boundaries for apps include Prompt Injection, Insecure Output Handling, Sensitive Information Disclosure, Excessive Agency, and Overreliance; the 2026 GenAI LLM Top 10 (published 2026-08-03/04) is the current canonical list and maps to NIST, MITRE ATLAS, and CWE.
- quote: "LLM08: Excessive Agency — Granting LLMs unchecked autonomy to take action can lead to unintended consequences... LLM09: Overreliance — Failing to critically assess LLM outputs can lead to compromised decision making"
- url: https://owasp.org/www-project-top-10-for-large-language-model-applications/
- source_type: primary
- published: 2026-08-04 (2026 release); 2023 v1.1 historical list archived
- confidence: high

### [14] Runtime guardrails in production GenAI systems are framed as deploying controls that detect policy violations, hallucinations, and data leakage and block bad outputs before they reach users (Guardrails AI product positioning; Guardrails AI announced joining Harvey on 2026-09-09).
- quote: "Deploy runtime guardrails that detect policy violations, hallucinations, and data leakage. Block bad outputs before they reach users."
- url: https://docs.guardrailsai.com/
- source_type: primary
- published: 2026-09-09
- confidence: medium
